# C009 / T01b 持久化投影任务

## 行为与边界

- `publishAfterCommit` 在当前数据库事务写入 `t_kds_projection_intent`；没有事务时创建短事务。这个方法必须在源事务提交前调用。提交回调只提交任务 ID 到有界执行器，不申请新连接。
- 加菜在原事务中记录，提交后的加菜 hook 不再重复记录。普通自动接单的订单头更新与任务记录共用短事务；HTTP 打印不搬进该事务。手动接单 `/admin/order/receiving` 有事务边界。
- KDS 整单完成的意图通过 BEFORE_COMMIT 事件监听记录；WS 广播仍在 AFTER_COMMIT。整单聚合服务加入事务。
- hook 的可靠记录阶段不能被可选工单异常处理吞掉。未接单订单只保留意图，直到当前源订单满足既有接单/取消/关闭条件才生成投影。
- 任务、投影和下发事件使用同一数据源。消费事务锁定任务行，写投影/事件并删除任务一起提交。失败回滚；另一个短事务将下次尝试设置为 30 秒后，递增 attempts。错误不会删除任务。
- 同订单先处理较早任务，后续任务不得越过失败任务；不依赖“最近两天”恢复。重复消费已确认任务无副作用，投影哈希避免内容未变化时重复下发。
- 专用单线程每 5 秒扫描最多 32 条，投递仍使用 2 工作线程、128 队列、130 总在途预算。队列拒绝保留数据库任务；停机后靠下一实例扫描恢复。`app.scheduling.enabled=false` 会关闭后台扫描，只适用于隔离调试环境。

这是数据库投影的可靠任务机制，不是打印机的分布式事务；没有引入重启后自动重打票据。升级前丢失、且未记录意图的历史操作不能靠新表重建，旧源订单对账仍保留。生产数据库自身持久性、复制、备份和故障切换属于 T22 验收。

## 迁移与回退

1. 备份并核实目标数据库，显式执行 `docs/db_migration_kds_projection_intent.sql`。新安装也需执行；应用不自动建表。
2. 确认 InnoDB、全部字段及三个索引。启动只读检查不通过会阻止新版本启动。
3. 再部署新 JAR，检查队列年龄、错误日志及厨显补拉。多实例发布期间旧实例产生的操作没有新意图，只能依赖旧补偿；可靠性验收应在全部实例升级后开展。
4. 应用回退时保留任务表及其行；旧版不会消费它们，重新升级后恢复。不清空表、不按创建时间删除未处理任务。

## 本地验收

| 场景 | 验收标准 | 证据测试 |
|---|---|---|
| 回滚、插入异常被上层捕获 | 业务写入与意图一起回滚，不发提交唤醒 | CashierKdsProjectionIntentTest |
| 提交唤醒拒绝、扫描满队列 | 数据库行保留；最多32条投递，首次拒绝即停止 | 同上 |
| 写投影后异常 | 投影写入回滚，意图保留并增加重试次数 | 同上 |
| 磁盘恢复 | 关闭连接、使用新数据源打开磁盘H2后完成任务 | 同上 |
| 同单顺序、并发重复消费 | 不越过前序；一份投影副作用、一份确认 | 同上 |
| 接单与意图一致 | 自动接单更新失败/意图写入失败都不产生半提交 | 同上 |
| 完成事件的事务阶段 | 原事务回滚无意图，提交时有ORDER_CLOSED意图 | 同上 |
| 未接单、重复完整投影 | 未接单无下发；接单后原子确认；重复内容只产生一个事件 | CashierKdsDeliveryServiceTest |
| 满连接池 | 两业务事务都返回，后台投影完成 | CashierKdsProjectionPoolTest |
| 缺表/索引、错误引擎 | 拒绝启动，不自动DDL | CashierKdsProjectionIntentReadinessTest |

磁盘H2重新打开验证应用恢复逻辑，不等同生产MySQL进程崩溃、断电或主从切换验证。

## 生产验收与诊断（尚未执行）

```sql
SELECT COUNT(*) AS pending, MIN(created_at) AS oldest, MAX(attempts) AS max_attempts
FROM t_kds_projection_intent;

SELECT id, order_id, attempts, next_attempt_ms, created_at
FROM t_kds_projection_intent
WHERE next_attempt_ms <= UNIX_TIMESTAMP(CURRENT_TIMESTAMP(3))*1000
ORDER BY next_attempt_ms,id LIMIT 32;
```

首次告警建议：最老任务超过 120 秒或同一任务 attempts>=10；未接单任务需要结合订单状态区分，不能自动删除。容量指标聚合应低频采集；监控数据库磁盘剩余空间，不能将持久化队列误当作无限存储。

在独立 MySQL 环境验证：未消费时终止应用并重启；投影事务中断后确认行未丢；双实例同时消费；持续制造数据库超时后恢复；压满有界队列；检查新表和同单查询 EXPLAIN。核实生产数据库事务表引擎、时间同步和实际连接池预算。不得用本地通过替代这些生产验收。
