# C009 / T05 Bootstrap 补投影与租约短事务

## 变更

旧首屏在锁定t_kds_delivery_consumer后查询所有缺口并逐单publish，异常被吞掉。新流程先短事务校验租约并关闭快照门禁，再在事务外做缺口检查和分页读取；返回前短事务再次校验device/epoch/token/有效期并登记游标。

- 缺口检查最多返回1个ID；缺口存在则返回HTTP503/code5030 BOOTSTRAP_PROJECTION_PENDING，不返回complete快照。
- 后台修复使用1个线程、16个排队门店、同店去重；每次最多32单、每单独立事务，事务超时5秒，缺口SQL设5秒statement预算。排队满不在请求线程执行，不删除源订单。
- 请求每次重试可唤醒下一批；进程退出后由下一次Bootstrap重试恢复。不是新增持久化任务系统，持久化源订单和T01b意图机制仍保留。
- 页面读取不持租约行锁，RENEW无需等待逐单投影；读页期间epoch变化或租约过期，结束校验返回409，旧请求不能更新投递游标。
- 未完成时bootstrap_base_cursor=Long.MAX_VALUE、bootstrap_required=1；缺口503/读失败/部分页之后ACK(0)或旧游标不能清除门禁。完整页登记实际baseCursor后，客户端才可最终ACK。

## 客户端及部署契约

503后保持RENEW（现有renewAfterMs=10000、lease=30000ms），建议1–5秒抖动退避重试首屏，不清空本地有效状态或把缺口当成空快照。分页期间也须续租；相同epoch续租不改变分页签名。pageToken现有10分钟有效期不延长，过期重新首屏；SQLite最终提交仍应等待全部页面完成。

无新增DDL。仍须满足T01b/T03既有迁移前置。客户端503重试、持续续租和完整分页提交的联调在T17/T22验证，不能把本机后端测试视为前后端上线完成。回退不删除任务、源订单或投影；旧服务器首屏可能恢复长事务问题，应监控续租延迟。

## 尚待生产验收

- 原近2天、rec_order且非cancelled的补投影筛选保持；更早历史缺口不能据此宣称已恢复。永久坏数据会持续503并记录订单ID，需修复源数据，不能改为跳过并返回完整。
- 单页最多100条不等于字节上限；大payload、businessDayOrders长事务/N+1及快照跨页一致性是其他审计范围。
- 5秒为SQL/事务预算，驱动网络故障硬截止、真实MySQL锁竞争与后台吞吐尚未压测。32单批次不是5秒整批截止。
- 在隔离MySQL准备100/1000/10000条缺口，记录恢复批次数、503比例、线程/队列上限、租约RENEW p95/p99；阻塞投影SQL期间续租应独立完成，不出现由补投影持有consumer行锁的等待。
- 测试修复失败、满队列、进程退出、epoch接管、分页token过期：源订单不丢；客户端不提交不完整快照；旧epoch请求不更新消费游标。72小时与生产压测仍归T22。
