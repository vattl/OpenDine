# KDS 厨房显示系统 产品需求文档（PRD 正式商用版）

## 1 项目概述

### 11 项目目标

对接自研点餐系统，实现**后厨无纸化、分屏分流、防漏单、实时出餐、岗位隔离**，完全适配烧烤店多岗分工：抓串岗、荤烤岗、素烤岗、海鲜岗、出餐核对岗。

### 12 运行环境

- 运行设备：安卓平板 / 安卓电视
- 运行载体：WebView / Uniapp 打包 APP（推荐 APP 壳，彻底防卡顿）
- 网络：店内局域网优先、外网兜底
- 页面模式：固定横屏、禁止旋转、禁止息屏常驻

### 13 核心解决问题

1. 解决小票丢失、糊掉、漏菜
2. 解决多单混单、分岗不清、谁烤不明确
3. 解决网页卡顿、DOM 堆积、长时间运行卡死
4. 解决断网丢单、重连刷新丢失数据
5. 解决抓串无法汇总、人工算串出错

## 2 整体业务架构

### 21 数据流

顾客点餐 小程序 / H5 → 后端服务 → WebSocket 实时推送 → KDS 各分屏
KDS 操作状态 → HTTP 接口回写后端 → 前台 / 收银台同步最新出餐状态

### 22 五屏标准岗位体系（烧烤店固定）

1. **抓串汇总屏（聚合所有菜品、统计总串数）**
2. **荤菜烤制屏**
3. **素菜烤制屏**
4. **海鲜 / 锡纸 / 特色屏**
5. **总出餐核对屏（全部完成菜品汇总）**

后台可自由配置：菜品属于哪一个屏幕。

## 3 订单完整状态机（核心、不能错）

### 31 单品状态（orderitemstatus）

0 = 待制作（新单未动）
1 = 制作中（已上炉 / 开始抓串）
2 = 已完成（烤制完毕可出餐）
3 = 已退菜（不显示、不计入出品）

### 32 整单状态（ordermainstatus）

10 待后厨接单
20 后厨制作中
30 部分出餐
40 整单制作完成
90 订单完结

### 33 页面颜色 UI 规则

灰色：待制作
黄色：制作中
绿色：已完成
红色：超时 / 加急订单

## 4 KDS 系统完整功能需求（正式开发版）

### 41 系统基础能力（必须开发）

1. 设备绑定屏幕类型（开机选择：抓串屏 / 荤菜屏 / 素菜屏 / 海鲜屏 / 总屏）
2. 横屏锁定、禁止息屏、页面常驻
3. 实时时间显示  今日接单统计
4. 新订单语音播报（叮咚  文字播报：新订单来了）
5. 断线自动重连、心跳保活
6. 本地离线缓存订单，断网不丢单
7. 联网自动同步差异数据
8. 防卡顿：**虚拟列表渲染**（只渲染可视区域订单）
9. 凌晨自动重置内存、自动清已完成归档
10. 禁止页面手动刷新导致数据丢失

### 42 实时订单接收功能

1. 新下单实时推送
2. 加菜实时插入订单
3. 退菜实时隐藏对应单品
4. 修改口味 / 备注实时刷新
5. 订单区分：堂食、打包、外卖
6. 加急订单置顶  红色高亮
7. 自动排序规则：加急优先  下单时间越早越靠前

### 43 分屏分流逻辑（烧烤核心）

1. 后端每个菜品绑定 `screen\_tag` 字段
2. KDS 启动读取自身屏幕类型，**只展示对应 screentag 菜品**
3. 抓串屏特殊逻辑：
  - **所有菜品全部显示**
    - **同菜品自动聚合汇总总数量**（重点防漏串）
    - 不按桌拆分，按品类汇总，方便备料抓串
4. 各烤制屏：只展示自己品类、干净不乱

### 44 订单页面展示字段（每一条必须有）

1. 桌号 / 取餐号
2. 下单时间、等待时长
3. 菜品名称
4. 数量（串 / 份）
5. 口味备注（微辣、免葱、多料等）
6. 单品状态标签
7. 整单备注

### 45 后厨操作功能（防漏单核心）

1. 单品【开始制作】按钮（状态→制作中）
2. 单品【制作完成】按钮（状态→已完成）
3. 单品【缺货异常】上报（同步前台禁止点单）
4. 整单一键全部完成
5. 已完成菜品自动下沉折叠，不占屏幕
6. 超时 10 分钟未制作自动变红预警

### 46 抓串屏专属功能（独有）

1. 全店所有待做菜品**自动汇总统计**
2. 例：油边总共 28 串、羊肉 36 串、金针菇 12 份
3. 支持勾选【已抓齐】
4. 抓串完成可标记分发至烤制岗
5. 清晰看到今日高峰备货量

### 47 数据同步机制

1. KDS 每次状态变更 **立即 HTTP 回写后端**
2. 后端实时同步到点餐端、收银端
3. 保证三端状态绝对一致

### 48 异常处理机制（商用必备）

1. WebSocket 15 秒心跳包
2. 断线 3 秒自动重连，无限重试
3. 断网期间所有操作缓存本地
4. 联网一次性同步所有本地变更
5. 自动去重重复订单
6. 过期订单自动归档（2 小时前已完成）
7. 防止 DOM 无限堆积导致页面卡死

### 49 权限机制

1. 不同屏幕只能操作自己岗位菜品
2. 不可修改价格、不可删除订单、不可修改历史数据

## 6 接口通信协议（开发标准）

### 61 WebSocket 实时推送

地址：`ws://你的域名/kds/ws`
推送事件类型：

- neworder 新订单
- updateorder 加菜 / 改备注
- cancelitem 退菜单品
- cancelorder 整单取消

### 62 KDS 回调接口（必须）

1. 更新单品状态

`POST /kds/item/status`
参数：itemid、status、screentype

1. 上报缺货

`POST /kds/item/lack`

1. 同步本地所有状态

`POST /kds/sync/all`

### 63 初始化拉取数据

`GET /kds/order/list`
参数：screentag、status

## 7 防卡死强制开发规范（最重要）

1. **必须使用虚拟列表**，不渲染屏幕外 DOM
2. 禁止整页刷新，所有更新局部 diff 刷新
3. 已完成订单自动折叠，不参与渲染
4. 定时垃圾回收内存
5. WebView 开启硬件加速
6. 禁止一切动画、过渡、特效
7. 长连接断线重连机制必须健壮
