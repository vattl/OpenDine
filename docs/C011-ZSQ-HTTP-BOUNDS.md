# C009/T08 真省钱 HTTP 边界

## 风险与范围

配送创建、询价、状态轮询和取消共用真省钱 HTTP 客户端。原实现使用非池化 JDK 连接，连接等待 15 秒、读等待 60 秒；在下游阻塞或 token 同时失效时，调度和业务请求会堆积并重复登录。

本项只调整 ZSQ 配送依赖。通用微信、飞鹅云打印与高德客户端的独立容量与超时策略不属于本任务，需在后续审计中单独评估。

## 已实施预算

`zsq` 配置的默认值：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `http-max-connections` | 4 | ZSQ 全局连接上限 |
| `http-max-connections-per-route` | 4 | 单远端路由上限 |
| `http-connection-request-timeout-ms` | 1000 | 连接池满时的最长租赁等待 |
| `http-connect-timeout-ms` | 2000 | 建连期限 |
| `http-read-timeout-ms` | 5000 | 首字节及读阻塞期限 |

启动时拒绝非正值或单路由大于全局连接数的配置。连接池租赁、连接和读取均有期限；失败由调用方现有错误处理或下一轮有界调度恢复，不在本项增加自动重试。

配置账号 token 失效时，只有仍持有当前失败 token 的首个调用者会登录。等待者若发现内存 token 已被替换则直接复用新 token，避免一次 401 放大为登录风暴。token 内容不会写入日志。

## 验收与生产验证

本地验证了连接池 request factory、预算门禁、并发 401 的单次刷新，以及订单跟踪、重发、取消和调度回归。T22 仍需在真实 DNS/TLS 慢链路及连接池耗尽条件下验证：1 秒租赁失败、2 秒建连失败、5 秒读取失败是否按预期返回，以及峰值下登录次数、活跃/等待连接和错误率。
