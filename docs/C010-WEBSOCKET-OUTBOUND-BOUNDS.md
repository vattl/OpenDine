# C009/T07 WebSocket 出站边界

## 目标

WebSocket 只用于实时唤醒或刷新提示；订单和收银投影的权威恢复路径仍是已有的 REST 游标接口。任何单一慢客户端不得阻塞提交回调、业务请求或其他会话。

## 实现

`WebSocketOutboundDispatcher` 是 KDS、菜单和收银唤醒三个 hub 的唯一服务端出站写入口：

- 每会话 FIFO，单写者，保持该会话内消息顺序；
- 全局固定 4 个 daemon 写线程，待调度会话队列最多 256；
- 每会话至多 32 条、64 KiB 待写数据。入队超限立即关闭该连接；
- 单次写超过 5 秒由看门狗关闭连接，并清空该会话待写数据；
- 连接关闭、写失败、执行器饱和均移除该会话，业务事件不会在调用者线程做网络 I/O。

配置位于 `app.websocket`，可根据真实峰值调整，但任何配置都必须保持有限。发送超时通过关闭 socket 尝试解除底层阻塞；JVM 或容器网络栈是否立即响应需要 T22 真实压测验证。

## 客户端恢复

KDS 厨显在重连后继续通过既有同步接口补拉；收银端以持久 `t_kds_delivery_event` cursor 补拉。菜单推送本来就是刷新提示，重连后重拉菜单即可。因此关闭慢消费者只降低即时性，不删减业务事实。

## 本地验收

- 同会话两条消息按提交顺序发送；
- 队列溢出关闭慢消费者；
- 被阻塞的写在配置期限后关闭连接；
- 既有收银 cursor 唤醒回归仍可到达在线会话。

生产验证归 T22：记录每个关闭原因、出站队列饱和、会话数和 socket 写阻塞持续时间，并在峰值及慢网条件下验证恢复时间。
