# 收银系统升级 — 后端架构与接口设计

## 一、系统整体架构（与现有系统兼容）

- **架构形态**：前后端分离 + 多门店 + 小程序 / 收银机 / 后台三合一  
- **前端**：收银机端（PC/平板）、顾客小程序点餐、运营后台（admin_panel）  
- **后端**：现有 Java 后端保持不变，仅扩展新包与新接口  
- **数据库**：MySQL，现有表（如 `t_order`、`t_order_detail`、`t_table`、`t_category`、`t_dish`、`t_user`、`t_admin` 等）**不修改**，仅**新增**扩展表  
- **部署**：单机 / 宝塔 / 服务器均支持  
- **角色**：老板 → 店长 → 收银员 → 顾客（通过现有 RBAC：t_admin + t_role + t_permission 扩展角色与权限码）

### 与现有系统关系

| 层次     | 现有                         | 升级扩展说明 |
|----------|------------------------------|--------------|
| 接口     | `/order/*`、`/dish/*`、`/admin/*` 等 | **全部保留**，新增 `/cashier/*`、`/admin/shop/*` 等前缀，不替换旧接口 |
| 数据库   | db_diancan、db_diancan_permission    | **不删不改**，仅执行 `db_diancan_cashier_ext.sql` 新增表 |
| 权限     | t_admin、t_role、t_permission        | 新增权限码（如 `cashier:operate`、`shop:manage`），映射到新接口 |

## 二、核心模块与后端包/接口归类

### 1. 基础设置模块

| 功能         | 现有接口/表                     | 扩展接口（新增） | 扩展表（新增） |
|--------------|----------------------------------|------------------|----------------|
| 门店管理     | 无                              | `GET/POST/PUT /admin/shop/*` | t_shop |
| 员工管理     | t_admin、/adminLogin、权限体系   | `GET/POST /admin/staff/*`（可选，或沿用 admin） | t_staff（可选） |
| 桌台管理     | t_table、/admin/table/*          | 保持现有；**GET /admin/table/status** 获取桌台状态（可选 ?number= 只查单桌，否则全量）；多门店时可选 `GET /admin/table/list?shopId=` | 可选 t_table 增加 shop_id（本阶段不改表） |
| 菜品分类     | t_category、/admin/category/*    | 保持现有                         | 无 |
| 菜品库       | t_dish、/admin/dish/*            | 保持现有                         | 无 |
| 支付方式     | 无                              | `GET/POST /admin/payment-method/*` | t_payment_method |

### 2. 前台收银核心模块

| 功能           | 现有接口/表           | 扩展接口（新增） |
|----------------|------------------------|------------------|
| 开台/加台/并台/转台/清台 | /order/table_status、/admin/table/out | POST /cashier/table/open、merge、transfer、clear |
| 快速点餐/改价/备注/做法 | /order/create、addDishes、/admin/orderDetail/* | POST /cashier/order/quickOrder、updatePrice、remark |
| 退菜/赠菜/折扣/抹零/优惠券 | /admin/orderDetail/delete_menu 等 | POST /cashier/order/refundDish、giftDish、discount、wipeZero、applyCoupon |
| 结账/挂单/反结账 | /admin/order/checkout 等 | POST /cashier/order/checkout、hang、unCheckout |
| 后厨打印       | /order/printContent、autoAcceptAndPrint | POST /cashier/print/kitchen（分单：烤炉/凉菜/饮品） |
| 外卖接单       | /admin/order/receiving 等 | 保持现有；扩展 POST /admin/order/thirdSync（美团/饿了么同步） |

### 3. 订单管理模块

| 功能         | 现有接口               | 扩展接口（新增） |
|--------------|------------------------|------------------|
| 今日/历史订单 | /admin/order/list、/order/history | 保持现有；新增 GET /cashier/order/today、/cashier/order/search |
| 订单状态     | transac_status、order_receiving | 保持现有枚举 |
| 订单搜索     | list 的 query 等       | GET /cashier/order/search?tableNumber=&startTime=&endTime=&cashierId= |
| 订单日志     | 无                     | GET /admin/order/log/{orderId}；表 t_order_log（新增） |

### 4. 库存与成本模块

| 功能           | 扩展接口（新增） | 扩展表（新增） |
|----------------|------------------|----------------|
| 原材料入库     | POST/GET /admin/material/inbound | t_material、t_stock_in |
| 原材料出库/消耗 | POST/GET /admin/material/outbound | t_stock_out |
| 库存预警       | GET /admin/material/alert        | 基于 t_material 当前库存与预警阈值 |
| 每日成本核算   | POST /admin/cost/daily           | t_daily_cost（可选） |
| 进销存日报/月报 | GET /admin/report/inventory      | 基于 t_stock_in、t_stock_out 统计 |

### 5. 会员营销模块

> 隐私约束：会员对外唯一标识使用 **手机号 phone**，`openid` 仅在后端与微信打通及数据库关联时内部使用，不在对外 API 入参/文档中暴露。

| 功能           | 现有/扩展说明        | 扩展接口（新增）                        | 扩展表（新增） |
|----------------|----------------------|-----------------------------------------|----------------|
| 会员注册/充值/积分 | t_user 含 points、balance 等 | POST /admin/member/recharge、addPoints  | t_user.balance |
| 充值赠送/满减/优惠券 | t_coupon、t_user_coupon | 保持现有 + 规则配置                      | 无或 t_member_rule |
| 会员消费记录   | 订单通过手机号间接关联 openid | GET /admin/member/consumption（按 phone 查询） | 基于 t_order 统计 |
| 会员画像       | 无                   | GET /admin/member/profile?phone=xxx     | 基于 t_order、t_order_detail 聚合，入参只暴露手机号 |

### 6. 外卖对接模块

| 功能           | 扩展接口（新增） |
|----------------|------------------|
| 美团/饿了么接单 | POST /admin/third/order/sync（自动落单） |
| 自动打印       | 沿用 /order/autoAcceptAndPrint 或 /cashier/print/kitchen |
| 订单状态回传   | POST /admin/third/order/statusPush |
| 平台对账       | GET /admin/third/reconciliation |

### 7. 日结与财务对账模块

| 功能           | 扩展接口（新增） | 扩展表（新增） |
|----------------|------------------|----------------|
| 收银员交班对账 | POST /cashier/shift/handover、GET /cashier/shift/current | t_shift（可选） |
| 门店日结       | POST /admin/daily/settle、GET /admin/daily/summary | t_daily_stat |
| 营业收入明细   | GET /admin/daily/income?date=&shopId= | 基于 t_order、t_payment 统计 |
| 退款/优惠/抹零明细 | GET /admin/daily/deduction | 基于 t_order.discount_amount 等 |
| 支付渠道对账   | GET /admin/daily/byChannel | t_payment（新增） |
| 每日毛利       | GET /admin/daily/grossProfit | 营业额 - 原材料成本（t_daily_cost） |

### 8. 数据报表模块

| 功能           | 现有接口                   | 扩展接口（新增） |
|----------------|----------------------------|------------------|
| 营业日报/周报/月报 | /admin/order/statistics*   | GET /admin/report/daily、weekly、monthly |
| 菜品销量榜     | statisticsDishSales        | 保持现有；GET /admin/report/dishRanking |
| 收银员业绩     | 无                         | GET /admin/report/cashierPerformance |
| 门店利润分析   | 无                         | GET /admin/report/shopProfit |
| 同比/环比      | 无                         | GET /admin/report/compare?type=yearOnYear |

### 9. 权限与安全模块

| 功能           | 现有               | 扩展说明 |
|----------------|--------------------|----------|
| 角色与数据范围 | t_role、t_permission | 新角色：店长、收银员；新权限码见下 |
| 关键操作日志   | 无                 | 新表 t_operation_log；接口 GET /admin/log/operation |
| 防作弊         | 无                 | 反结账/改价频率限制、敏感操作二次确认（后端策略） |
| 数据备份       | 运维层             | 不在此 API 范围 |

**新增权限码建议**：`shop:manage`、`cashier:operate`、`material:manage`、`daily:settle`、`report:view`、`log:view`。

## 三、后端接口核心（必做）与现有对应

| 必做项         | 现有接口                     | 扩展/说明 |
|----------------|------------------------------|-----------|
| 登录鉴权       | /adminLogin、JWT、权限码     | 收银机端复用 /adminLogin 或新增 /cashier/login，JWT 区分 client=pos |
| 桌台状态       | /order/table_status、/admin/table/list | 保持；**GET /admin/table/status** 获取桌台（B 端，可选 ?number= 单桌否则全量；传桌号且该桌有 order_no 时按订单号查询返回 orderList，每条订单含 goods_list 菜品明细）；可选 GET /cashier/table/statusMap（按区域聚合） |
| 点餐/加菜/退菜 | /order/create、addDishes、/admin/orderDetail/delete_menu | 保持；收银机封装 POST /cashier/order/submit、/cashier/order/refundDish |
| 结账           | /admin/order/checkout        | 保持；收银机 POST /cashier/order/checkout |
| 打印指令       | /order/printContent、autoAcceptAndPrint | 保持；收银机 POST /cashier/print/kitchen（分单类型参数） |
| 订单查询       | /admin/order/list            | 保持；收银机 GET /cashier/order/today、search |
| 日结对账       | 无                           | 新增 POST /admin/daily/settle、GET /admin/daily/summary |
| 数据统计       | /admin/order/statisticsCategorySales、statisticsDishSales | 保持；新增 /admin/report/* |

## 四、业务流程（与现有一致并细化）

1. **开台** → 2. **点餐** → 3. **后厨打印** → 4. **加菜/退菜** → 5. **结账** → 6. **打印小票** → 7. **清台** → 8. **交班日结**

现有接口已覆盖 1–7；第 8 步交班/日结通过新增 `t_daily_stat` 与 `/admin/daily/*`、`/cashier/shift/*` 完成。
