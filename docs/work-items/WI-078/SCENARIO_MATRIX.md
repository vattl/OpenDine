# Scenario Matrix — WI-078

| Scenario ID | Category | Description | Expected Outcome | Verification Method |
| :--- | :--- | :--- | :--- | :--- |
| **SM-01** | WebSocket Lifecycle & Auth | Cashier connects to `/ws/v1/notify?client_type=CASHIER&shop_id=1&token=<jwt>` (or lease headers); Mini Program connects with `client_type=MINI_PROGRAM&shop_id=1&openid=o_123` | Session registered in `UnifiedSessionRegistry` and receives `CONNECTED` frame; invalid cashier credentials rejected with `POLICY_VIOLATION` | Unit test `UnifiedNotificationChannelTest` |
| **SM-02** | Heartbeat & Dynamic Context Rebinding | Client sends `{"frame_type":"PING"}` and `{"frame_type":"BIND_CONTEXT","shop_id":2,"openid":"o_456"}` | Server replies with `PONG` (including `server_head_seq_id`) and rebinds session index from shop 1 to shop 2 | Unit test `UnifiedNotificationChannelTest` |
| **SM-03** | Dynamic Shop Timeout Config Validation | Admin calls `GET /admin/shop/notification-config` and `PUT /admin/shop/notification-config` with valid (`20` min) and out-of-range (`3` min, `180` min) thresholds | Default config returns `enabled=true, prepTimeoutMinutes=15, timeoutRepeatIntervalSeconds=60`; valid update persists; `<5` or `>120` rejected with HTTP 400 / error code | Unit test `ShopNotificationConfigServiceTest` |
| **SM-04** | Dynamic Order Prep Timeout Watchdog | Shop 1 sets threshold to `10` min (`enabled=true`), Shop 2 disables timeout (`enabled=false`). Paid uncompleted orders exist at 12 min elapsed | Watchdog publishes `ORDER_PREP_TIMEOUT` (`P0`, `message_id = ntf_timeout_<orderNo>_stage1`) for Shop 1 only, deduplicating subsequent scans | Unit test `OrderTimeoutWatchdogSchedulerTest` |
| **SM-05** | New Order Paid Realtime Push | `PaymentSuccessHandler.run()` completes for a paid order | Publishes `NEW_ORDER_PAID` (`P1`) to the order's `shop_id` cashier sessions and persists to `t_realtime_notification` | Unit test `UnifiedNotificationChannelTest` |
| **SM-06** | New Coupon Granted Online WS + Offline Subscribe Fallback | `ICouponServiceImpl.receiveCoupon(openid, couponId)` succeeds for online user vs offline user | Online user receives `COUPON_GRANTED` (`P1`, `aggregation_key=COUPON_GRANTED`) via WebSocket; offline user triggers `WechatCouponSubscribePushService` when template is configured | Unit test `UnifiedNotificationChannelTest` |
| **SM-07** | Incremental Sync (`GET /cashier/notifications/sync`) & Multi-Device ACK (`POST /cashier/notifications/ack`) | Cashier reconnects with `last_seq_id` to pull missed notifications, then ACKs `message_ids` | Sync returns unread non-expired items with `seq_id > last_seq_id` and `server_head_seq_id`; ACK marks `read_status=1` and broadcasts `ALERT_DISMISSED` to all cashier sessions of the same `shop_id` | Unit test `UnifiedNotificationChannelTest` |
| **SM-08** | Dual-Publish Compatibility Bridges | `CashierEventWebSocketHub` and `DishMenuPushService` broadcast events | Events are sent to both legacy `/ws/cashier-events` / `/ws/menu` and unified `/ws/v1/notify` | Unit test `UnifiedNotificationChannelTest` |
