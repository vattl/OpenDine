# Acceptance Report — WI-024

Decision: ACCEPTED

## Acceptance Evidence

- JSAPI 预支付尝试已持久化并绑定订单、门店、商户配置版本、金额、付款人和商户单号。
- 相同请求复用有效尝试；金额、付款人或路由变化时，旧交易必须被权威查询并关闭后才能创建新交易。
- 退菜、数量、改价、折扣和加菜等金额变更入口在写入前处理活动微信交易；退菜在库存、明细和 KDS 副作用前执行保护，未知或已支付状态阻断变更。
- 顾客已拉起密码框时，退菜与支付按订单锁竞争：支付先成功则退菜零副作用失败；退菜先执行则旧微信单关闭后才允许改金额。
- 回调精确匹配尝试、金额、交易类型、商户、AppID、openid 和 transaction_id；冲突不入账且不释放重复支付保护。
- `t_payment_ledger` 已确立为权威资金事实：微信回调先落流水再更新订单；流水或订单任一步失败均在同一事务回滚。
- 收银手工结账先收敛活动 JSAPI，再落流水、最后更新订单；不能覆盖已由回调写入的不同成功资金事实。
- 当前订单净应付与微信实付必须完全一致；252 元旧支付不会结算到已降为 237 元的订单。
- API 文档与 V026 迁移已同步；专项、全量测试和可运行 JAR 构建通过。

## Scope Boundary

本决策只接受服务端能力。外部小程序/收银消费者仍为 HANDOFF_PENDING，必须按 `API_CONSUMER_HANDOFF.md` 清理缓存支付参数、刷新订单并处理冲突后，另行完成跨仓端到端验收。
